# Exploratory extension after the primary results
The locked cue model failed when urgency changed meaning. Test whether past closed tickets provide enough feedback for recovery. Lock this extension before generating new streams. Each of 10 new seed blocks has three consecutive 32-job periods: dispatch, museum handoff, dispatch again. The planner receives no phase, family, seed, job key or change notification. At job start snapshot a table formed from the last 16 closed tickets across the whole stream, with two pseudocounts per cue distributed in proportion to the development table. On closure observe cue and revealed final ticket whether or not the task succeeded. This assumes complete feedback even for blocked jobs. Report comparisons against frozen checked, checked greedy and conservative planning with the same verification, in both metadata regimes. Report all periods, including return-shift regressions. This selected method and stress sequence are exploratory. Never retroactively change the primary hypotheses or estimate.
